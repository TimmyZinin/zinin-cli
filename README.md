# ZININ CLI

**AI-инженер в твоём терминале.** Пилотируемый AI, не автопилот — управляй и понимай.

Авторский AI-харнес Тима Зинина: собственный REPL, мульти-LLM, ведёт за руку через установку Claude Code и Codex, учит, как устроен AI, пока ты работаешь.

## Установка — одна команда

**macOS / Linux:**
```sh
curl -fsSL https://zinin.ai/install | sh
```

**Windows (PowerShell):**
```powershell
irm https://zinin.ai/install.ps1 | iex
```

Без Node, без Homebrew — ставится один бинарь в PATH. Потом просто:
```sh
zinin
```

## Команды

| Команда | Что делает |
|---------|-----------|
| _(просто пиши)_ | разбор бизнеса, контент, автоматизации — обычным языком |
| `/setup` | проверит и поставит Claude Code / Codex |
| `/call` | позвать Тима на разговор (живой инженер, помощь с настройкой) |
| `/model` | сменить LLM (бесплатные / платные) |
| `/help` | меню |
| `/exit` | выход |

## Движок

Мульти-LLM с бесплатными моделями по умолчанию — ничего настраивать не нужно. Свой ключ OpenRouter (опционально, для прямого доступа):
```sh
export OPENROUTER_API_KEY=...
```

## `zinin ps` — обзор всех сессий

Одна таблица: одна строка на сессию, только чтение источников, никаких действий
над сессиями. Флаги: `--watch [N]` (обновление раз в N секунд, по умолчанию 5),
`--json` (машинный вывод), `--stuck-minutes N` (свой порог stuck для всех
движков), `--sources mac|newa|all`, `--help`.

### Состояния и доказательства

Каждое состояние имеет точный сигнал; при конфликте сигналов выигрывает более
высокий приоритет.

| Приоритет | Состояние | Сигнал-доказательство |
|---|---|---|
| 1 (высший) | `done` | последняя непустая строка TO-S0.md или REPORT-S0.md содержит «ГОТОВ»/«ИТОГ» |
| 2 | `closing` | status.json: `stop_requested=true` при живом воркере (live≠false) |
| 3 | `limit` | недельный лимит ≥ 95%, либо в хвосте транскрипта/окна есть rate_limit/403/limit reached |
| 4 | `waiting-tim` | последняя строка TO-S0.md: «вопрос»/«ждём Тима»/«блокер»/«нужен Тим»; или окно Claude: «What should Claude do instead» |
| 5 | `starting` | tmux-сессия/окно моложе 120 секунд и ходов ещё нет |
| 6 | `stuck` | нет движения дольше порога движка (см. ниже), а сессия рабочая |
| 7 | `working` | status.json `state=running`; глиф ◑/◐/✳ в заголовке окна; attached tmux |
| 8 (низший) | `idle` | всё наблюдаемо тихое: глиф ○, «\| idle» в заголовке, `state=idle` |

Порог `stuck` по движкам: **claude — 20 минут** (при работе Claude непрерывно
пишет в транскрипт и крутит индикатор; 20 минут тишины — скрытый запрос или
зависание; компактификация занимает минуты, не десятки минут); **kimi — 30
минут** (рабочий цикл: ход до 600 секунд плюс ожидание следующего поручения до
1800 секунд — легальный простой между ходами); **codex — 30 минут** (тот же
покадровый цикл, что у kimi); **unknown — 30 минут**. Флаг `--stuck-minutes N`
задаёт порог для всех движков разом.

### Откуда берутся данные

- **mac**: заголовки окон Terminal (osascript) + последняя строка вкладки,
  `ps` по tty, транскрипты `~/.claude/projects/*/*.jsonl`, лог `~/apparat/runs/s0-plan-*.md`.
- **newa**: `/home/agents/work/<name>/` (meta.json, status.json, turns/, TO-S0.md,
  REPORT-S0.md, TASK*.md), `tmux ls` (сессии `af-*`), `/proc/meminfo`, `df`.
  С Мака newa читается по ssh (`ZININ_PS_NEWA_CMD`, по умолчанию
  `ssh -o BatchMode=yes newa`) той же командой `zinin ps --sources newa --json`;
  при недоступности футер честно пишет `newa: недоступна`. Транскрипты Claude
  читаются хвостом 64 КБ и только за окно 24 ч (`ZININ_PS_TRANSCRIPT_MINUTES`),
  обогащают строку окна (движение, ошибки), а не порождают свои строки.

Колонки: id, машина, движок и модель, задача, состояние, минуты без движения,
во что упёрлась (последняя ошибка), что нужно (последний вопрос к Тиму),
контекст %, недельный лимит %; в футере — свободная память и диск машины.

## Приватность

Телеметрия собирает только метаданные событий (никогда — текст твоих запросов). Отключить:
```sh
export ZININ_NO_TELEMETRY=1
```
